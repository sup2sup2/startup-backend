# 위험도 캐시 A/B 부하 테스트 결과

- 측정일: 2026-09-28
- 대상: `https://startup-backend-t4qw.onrender.com`
- 환경: Render 무료 Web Service + Render 무료 Key Value + Aiven 무료 MySQL
- 스크립트: `load-tests/storm-read.js`
- 프로필: 5→15→30→50 RPS, 3분 15초
- 요청 비율: 위험도 70%, 신고 목록 20%, 강우량 10%

두 테스트는 같은 배포 환경과 시나리오에서 실행했습니다. OFF 테스트는 `RISK_CACHE_ENABLED=false`, ON 테스트는 `RISK_CACHE_ENABLED=true`로 설정했습니다. 서울시 API를 과도하게 호출하지 않도록 강우 공공데이터 Redis 캐시는 두 테스트 모두 활성화했습니다.

| 지표 | 위험도 캐시 OFF | 위험도 캐시 ON | 변화 |
|---|---:|---:|---:|
| 완료 요청 | 3,548 | 3,670 | 3.4% 증가 |
| HTTP 실패 | 0 (0.00%) | 0 (0.00%) | 동일 |
| 전체 평균 | 1,067.79ms | 256.96ms | 75.9% 감소 |
| 전체 p95 | 4,143.43ms | 663.79ms | 84.0% 감소 |
| 위험도 평균 | 1,166.18ms | 190.52ms | 83.7% 감소 |
| 위험도 p95 | 4,187.66ms | 393.52ms | 90.6% 감소 |
| 최대 응답 시간 | 8,081.45ms | 1,145.65ms | 85.8% 감소 |
| Dropped iterations | 126 | 4 | 96.8% 감소 |
| 최대 사용 VU | 142 | 23 | 83.8% 감소 |

캐시 OFF에서는 전체 p95 1초 미만과 위험도 p95 800ms 미만 임계값을 통과하지 못했습니다. 캐시 ON에서는 두 응답 시간 임계값과 실패율 1% 미만 기준을 모두 통과했습니다. 위험도 캐시는 같은 요청 목표를 처리하는 동안 긴 응답 대기와 필요한 동시 VU를 크게 줄였습니다.

`Dropped iterations`는 설정한 시점에 시작하지 못한 반복 요청입니다. 126건에서 4건으로 줄어 목표 요청 속도를 더 안정적으로 따라갔습니다. 전체 구간 평균 처리량은 램프 상승과 하강 구간을 포함하므로 최대 처리 능력을 뜻하지 않습니다. 50 RPS는 이 테스트의 순간 최대 목표값입니다.

이번 결과는 공유 무료 인프라에서 조건별로 한 번씩 실행한 비교입니다. 캐시의 효과를 확인하는 근거로 사용할 수 있지만 서비스의 최대 수용량이나 장기 안정성을 보장하지는 않습니다. DB 쿼리 수는 별도 계측하지 않았으므로 감소량을 수치로 주장하지 않습니다.
